# Лабораторная работа 2.3 (№ 9). Планирование пути

Вариант № 13, нечётный. RoboCake Beginner строит маршрут алгоритмом A* и отрабатывает его с обратной связью по колёсной одометрии. Склад загружается из пакета `lab2_2_cycle`. Его `warehouse.yaml` с PGM задаёт двумерную карту, а `warehouse.world` содержит соответствующие стены и стеллаж в Gazebo.

## Зависимости и запуск

ROS Noetic, Catkin и Gazebo 11. Нужны оба пакета лабораторных в одном рабочем пространстве и закреплённый RoboCake Beginner (ревизия `ef4893ae410cc611604126bd3c798c527565b61d`). Общий скрипт репозитория `scripts/fetch_robocake.sh` подготавливает upstream. Образ из корневого Dockerfile в `docker/` включает нужные пакеты ROS, в том числе `map_server`, `costmap_2d`, RViz, xacro, `gazebo_ros_control`, `gazebo_plugins` и ros-controllers. Для нативной установки список зависимостей пакета находится в `package.xml`.

Команды для уже подготовленного и собранного рабочего пространства (путь `/catkin_ws` внутри контейнера):

```bash
source /opt/ros/noetic/setup.bash
source /catkin_ws/devel/setup.bash
roslaunch lab2_3_path_planning demo.launch
```

Лабораторные 2.2 и 2.3 запускаются отдельно, поскольку используют общие имена топиков, фреймов и контроллеров. По умолчанию робот стартует в точке `(-1.10, 0.0)`, его цель находится в `(1.10, 0.0)` за центральным стеллажом. Параметры `x`, `y`, `yaw` меняют позу старта в метрах и радианах, а `goal_x` и `goal_y` меняют автоматическую цель. Для ручного задания цели запустите с `autostart:=false` и укажите точку инструментом **2D Nav Goal** в RViz. При движении этот же инструмент заменяет текущую цель. Угол инструмента игнорируется. `gui:=false` и `rviz:=false` отключают окна Gazebo и RViz соответственно.

## Карта, одометрия и A*

- `/map` публикуется `map_server`. В `/costmap_node/costmap/costmap` публикуется полная весовая сетка `nav_msgs/OccupancyGrid`, которую формируют статический слой и слой инфляции. В RViz обе карты включены, полупрозрачный слой затрат можно переключать отдельно.
- `robot_radius` задаёт радиус описанной окружности правильного шестиугольника (по умолчанию 0,12 м). `inflation_radius` задаёт дальность инфляции (0,40 м), а `cost_scaling_factor` определяет экспоненциальное затухание стоимости (8,0 м⁻¹). Планировщик использует запас на дискретизацию сетки и `clearance_margin` из `planner.yaml`. Радиус инфляции должен покрывать сумму радиуса робота, этого запаса и диагонали клетки. Настройки меняются при перезапуске launch. При замене `costmap_config` сохраняйте систему координат `map`, полную публикацию сетки, слой `inflation_layer` и нулевой `footprint_padding`, чтобы расчёт порога оставался согласован с контуром.
- `localization_publisher` устанавливает статическое преобразование `map → odom` с позой спавна. `diff_drive_controller` по состоянию колёс публикует `/diff_drive_controller/odom` и `odom → base_link`. Узел планирования преобразует полученную позу в `map` через TF. Обе карты используют этот же глобальный фрейм. При сбросе симуляции с телепортацией робота требуется заново запустить демонстрацию. Оценка положения накапливает ошибку колёсной одометрии.
- A* рассматривает восемь соседей. Для диагонали обе смежные боковые клетки должны быть проходимы. Стоимость ребра равна длине шага, умноженной на `1 + cost_weight × cost / 100`. Евклидова эвристика остаётся допустимой при неотрицательном `cost_weight`. Неизвестные клетки и клетки с высоким риском столкновения закрыты. Путь оптимален по заданной стоимости на графе сетки.
- Контроллер на 20 Гц сравнивает измеренную позу с очередной точкой пути, корректирует курс и снижает линейную скорость при приближении. Маршрут виден в `/path_planner/path`, состояние в `/path_planner/status`, команды поступают напрямую в `/diff_drive_controller/cmd_vel`. Непроходимая цель или потеря свежей одометрии приводит к остановке.

## Ультразвуковая остановка

В модели RoboCake сохранён штатный центральный дальномер `/proximity_front`. Расширение xacro добавляет `/proximity_front_left` и `/proximity_front_right` с поворотами ±30°. Все три используют модель ультразвукового дальномера Gazebo и публикуют `sensor_msgs/Range` с типом `ULTRASOUND`. Боковые ИК-датчики исходной модели сохраняются.

При дальности до 0,12 м по любому из трёх каналов, при потере свежих показаний или при получении некорректного измерения узел отправляет нулевую команду. Движение продолжается, когда все три дальномера показывают больше 0,15 м. Эти пороги и время ожидания изменяются в `planner_config`. Слой инфляции строится по известной карте. Появившееся перед роботом препятствие вызывает паузу, объезд незамеченного на карте объекта автоматически не строится.

```bash
rostopic echo /path_planner/status
rostopic echo -n1 /diff_drive_controller/odom
rostopic echo -n1 /proximity_front
rostopic echo -n1 /proximity_front_left
rostopic echo -n1 /proximity_front_right
```

Проведена статическая проверка файлов. Сборка Catkin, запуск Gazebo и RViz, точность движения и дальномеры в симуляции требуют проверки при запуске.
